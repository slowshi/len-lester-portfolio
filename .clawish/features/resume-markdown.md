# Resume markdown
> `content/lenlester_resume.md` is the resume source; PDF in `public/resume/` is exported manually.

## Key Decisions

**Resume vs website:** Resume promotes impact (customer growth, acquisition, shipping velocity). Website explains skills and concrete work. Do not copy site paragraphs into the resume verbatim.

**ScribbleVet on resume:** Senior Software Engineer, 10/2023 – Present. Include growth to 5,000+ customers and Instinct Science acquisition (2026). Emphasize frontend ownership, Elixir billing work, Coder workspaces, AI release tooling — without repo names.

**Laslow Labs on resume:** Owner & Developer; indie shipping and portfolio monetization — not monorepo jargon.

## External Constraints

- PDF at `public/resume/lenlester_resume.pdf` may lag markdown until user exports a new file.
- Resume uses standard Markdown structure (`#` name, `##` sections, `###` roles). Do not reintroduce Google Docs export escapes (`\-`) or tab-aligned contact lines.

## Known Gotchas

- Updating markdown alone does not update the live Resume nav link until PDF is replaced.
